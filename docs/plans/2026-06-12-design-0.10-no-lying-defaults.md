# causal 0.10 — No Lying Defaults

**Status: DESIGN — adversarially pressure-tested 2026-06-12 (five passes:
correctness, resilience, naming/DX, a full API audit, then a test-suite
consumer pass — all with the maintainer).** One proposal was retracted under attack and
three corrections plus one pre-code decision were found that block the
*in-flight 0.9 work* (partitioned runner), not just this design — marked
⛔ BLOCKING below. The resilience pass
additionally hardened four points: label-keyed derivation (positional keying
is deploy-brittle — **also affects shipped 0.9 dedup**), version-checked fold
cache, DLQ-preserved effect entries, and the transient-retry ceiling. The
naming/DX pass retracted `detach!` in favor of the declared `workflow_id`
identity (§3) and decoupled domain naming from storage vocabulary in one
coordinated rename — superseded by the fourth pass's final vocabulary
(`subject` / `workflow` / `NAME` — Primitive 1; ripple accepted: "it's
worse if we get it wrong"). The API-audit pass (see its section) ruled:
structs-only facts, label-free `events!`, the `state_of` read duo with
`engine.snapshot`/the eager registry deleted, `INVARIANT` on the
aggregate, `with_effect_store`, `on_terminal_failure`, and shape-gated
subject omission. Everything here assumes
greenfield freedom: nothing downstream is in production; no migration
scaffolding is owed.

## The principle

Every production bug found in the rootsignal archaeology (2026-06-10 →
2026-06-12) traced to the same root: **a framework default that lies.**

| Lying default | What it cost |
|---|---|
| `stream_id` defaults to `Uuid::nil()` | Fan-in aggregates (rootsignal curiosity) silently folding one global blended stream; per-entity reads impossible and *looking* possible |
| Registry reads look free, keying invisible at call site | `ctx.aggregate()` singleton-per-engine; cost and meaning decided by an `id_fn` in another module |
| `settle()` waits on every consumer's global cursor | One slow reactor anywhere blocks every correlation's settle — "settled" was a lie under load |
| Dedup-hit silently keeps the old payload | Nondeterministic producers (minted UUIDs, unmemoized LLM calls) corrupted nothing *visibly*; the reactor believed an output that never landed |
| Reactors get ambient clock/rng/HTTP | Determinism is an audit instead of a property; the audit found zero `ctx.remember` call sites and pervasive `new_v4()` in payloads downstream |
| No-DLQ mode block-retries forever | One poison event wedges the world, silently |

0.9 (stream identity required, divergence check, partitioned runner, ack-floor
checkpoints, batch-emit atomicity) fixes the first four. 0.10 is the remaining
set, plus the three blocking corrections to 0.9.

## ⛔ BLOCKING-1: incremental fold state in the partition worker

**This is a correction to the 0.9 partitioned-runner design, where it is
currently filed under "known issues / deferred (snapshot acceleration)." It is
not deferrable.**

Fold-on-read means every `react()` re-folds its aggregate's subject
history from genesis. For a per-workflow aggregate on a long-lived
workflow (rootsignal's `PipelineState`: thousands of events per run, fat
payloads, ~30 reactors reading it per trigger, every trigger appending),
that is **O(n²) in workflow length**, paid in deserialization of the largest
payloads in the system. The serial registry was amortizing this cost
incrementally; fold-on-read un-amortizes it. It bites at thousands of events,
not 10⁶.

**Fix — falls out of the partitioning design itself:** partitions are
FIFO; a per-workflow aggregate's events arrive in fold order at the
partition worker. The worker carries the fold forward **incrementally,
in-memory**, as a **version-checked cache** (keyed by subject + last-folded
position): before each read, check the subject-history head — if it moved
past the cached position, fold the gap. O(1) when subject ≡ workflow;
correct when not. Restart rebuilds from the history once, O(workflow). No
durability, no snapshot machinery.

The version check is not optional. Blind carry-forward assumes every
event of subject S arrives through this partition — true for run-style
aggregates (subject ≡ workflow), **false by design for shared subjects**,
which exist to be written from many workflows (two runs both appending to
one signal's history). The framework cannot verify the alignment assumption, so
the cache must not rely on it; a stale fold here is a silent wrong decision,
not an error.

Cross-partition reads (state of a *different* subject than the
trigger's) still fold-on-read; they are the rare case and position-bounded
snapshots remain the eventual fix there. Genuinely deferred.

## ⛔ BLOCKING-2: retry taxonomy — blanket bounded-retry amplifies outages

**Correction to "DLQ after max_attempts" as the universal failure path.**

Attack that found it: Neo4j is down for ten minutes → every graph-touching
reactor exhausts `max_attempts` → hundreds of triggers park as terminal
failures → a transient infra
blip that would have self-healed becomes a manual mass-replay incident.
Bounded-everything converts outages into operations.

**Fix — three error classes, declared by the reactor (or wrapped error type):**

| Class | Examples | Policy |
|---|---|---|
| **Transient** | connection refused, 5xx, timeout, 429 | backoff (capped exponential) up to a generous **time ceiling** (hours, not attempts), then terminal failure as `transient_exhausted` |
| **Poison** | trigger deserialization failure, divergent redelivery | immediate terminal failure — deterministic, retry is pointless |
| **Domain** | the operation itself failed meaningfully | bounded attempts → terminal failure fact |

Default for an unclassified `anyhow::Error`: domain (bounded). The API can be
as small as `causal::Error::transient(e)` / `::poison(e)` wrappers that the
runner downcasts for.

Transient is **ceilinged, not unbounded**, because misclassification is
inevitable (an LLM 400 for an oversized prompt is deterministic but looks
transient from a client adapter) and an unbounded-transient partition is a
silent permanent wedge. The ceiling is measured in **liveness time**
(tokio `Instant`, Primitive 6's two-clock rule), never as a `DateTime`
comparison — a chrono ceiling would silently break virtual-time testing
of exactly this machinery. `transient_exhausted` in the failure store is
distinguishable from poison, so a real outage's backlog is mass-replayable
as a class.

**Consequence the framework must demand, not just permit:** a terminal failure
fact in the middle of a workflow means the workflow's completion event never
arrives. Downstream completion logic MUST fold terminal-failure facts as
completion-with-error, or workflows leak (rootsignal: a run wedged "running"
busy-gates its source forever — the S3 wedge rebuilt with nicer logging).
The terminal-failure mapper docs carry this as a contract, and the built-in
terminal fact (see Primitive 5) adopts the **trigger's subject identity**
(`SUBJECT` + `subject_id`) as well as its workflow — folds read a
subject's history, so
landing it anywhere else would make "fold the failure into completion"
impossible by construction. The
downstream aggregate registers a fold for it like any other variant.

## ⛔ BLOCKING-3: the read-ahead window bounds pending work, not log distance

**Correction to the 0.9 partitioned-runner design, which frames window
exhaustion as a poison-event problem. It is also a slow-partition problem,
and the slow partition is the headline workload.**

The ack floor advances only over a contiguous-completed prefix. A 4-minute
Whisper react pins the floor at its trigger; everything the runner reads past
it — *including non-matching events it instantly acks* — sits in the window.
If the window is measured in events-read-past-floor, a hot log fills it during
those 4 minutes, the runner's ingestion stalls, and settle inherits the stall:
proving "no remaining work for chain C" requires every runner's ingestion to
have *reached* C's high-water. One stalled runner → every new workflow's
`settled()` waits → the global hostage problem, rebuilt, under exactly the
workload the redesign was for.

**Fix:** the window bounds **pending matching triggers** (queued + in-flight);
acked-past-floor positions are tracked in a compact ack-set (bitmap /
run-length) costing bytes, not window slots. A slow partition then accumulates
only its own backlog; ingestion never stalls on it; other chains' settles
never see it.

## ⛔ BLOCKING-4 (decision, not correction): partition key — workflow vs trigger-subject

**Must be decided with a written analysis before the partitioned runner lands.**
This is the design's one genuine black-swan candidate: 30+ reactors will
silently come to depend on whatever ordering the key implies, and switching
keys later changes concurrency semantics under all of them at once — the
textbook whole-codebase refactor. It costs a memo today.

The comparison, worked:

- **Causation provides most ordering under either key** — a trigger doesn't
  exist until its producer appended it; partitioning only affects *siblings*.
- **For run-style workflows the keys are identical** (run subject ≡ run
  workflow).
- **For shared-subject events, the subject key wins**: workflow
  partitioning lets two workflows touching subject X process X
  concurrently (the dedup/lifecycle race class); trigger-subject
  partitioning serializes X's events in log order regardless of producing
  workflow — subject gates become race-free by construction, and
  BLOCKING-1's fold cache gains true exclusivity over the trigger's own
  subject history (version-check needed only for cross-subject reads).
- **Subject partitioning's cost**: same-workflow siblings on different
  subjects may interleave. No constructed case breaks: position-bounded folds
  see everything up to the trigger regardless of partition processing order,
  and settle (per-workflow pending counters + high-water) is independent
  of the partition key.
- Slow-partition isolation (Whisper) is equivalent under both.

**Recommendation — dissolve the global key instead of picking it:** each
reactor declares its ordering requirement in the type —
`const ORDERING: Ordering = PerSubject (default) | PerWorkflow | None` —
and the runner partitions per `(consumer, declared key)`. "Reactors silently
depend on the key's ordering" becomes impossible: dependence is declared,
reviewable, and changeable per-reactor without touching the rest. The
irreversible global decision decomposes into local reversible ones. `None`
(commutative) gets per-event concurrency under `max_in_flight` as a bonus.
Settle is key-independent (per-workflow pending counters) under any of
this. If the memo rejects per-reactor declaration, fall back to global
trigger-subject — but the requirement is the decision memo before runner
code, not this particular answer.

## The six primitives

### 1. Facts are self-describing islands — identities declared, machinery derived

**The island principle (the test every macro prop must pass):** a prop is
a claim the event makes about itself and the world — never about
machinery. Machinery is derived:

```text
DECLARED ON THE EVENT (island claims)         DERIVED BY THE FRAMEWORK (machinery)
name         "I am called job_opened"     →   event_type on the wire; exact routing
subject_id   "the thing I'm about is in   →   storage stream {subject}-{subject_id};
              my job_id field"                fold locality (what state_of reads)
subject      "that thing is a job"        →   PerSubject partition key; $ce-job
              (defaults to `name`)            grouping; restore/snapshot keying
workflow_id  "the work I'm part of is     →   settle scope; partition membership;
              named by my job_id field"       lifecycle boundary. Omitted = inherited
occurred_at  "this happened at t"         →   (nothing — it is simply true)
causation    (automatic)                  →   lineage only, never semantics
```

A declaration reads as a sentence — what I'm called, what I'm about, what
work I'm part of:

```rust
#[causal::event(name = "job_opened", subject = "job", subject_id = "job_id",
                workflow_id = "job_id")]
struct JobOpened { job_id: Uuid, file_id: Uuid, occurred_at: DateTime<Utc> }
```

The two id axes exist because **things and work are different axes**: one
subject is touched by many workflows over its life (a signal: discovered
by run 12, corroborated by run 31, decayed by sweep 7); one workflow
touches many subjects while it lives (run 31: a page, two signals, a
completion). `subject_id` answers reads — "what is the state of signal
X?" = fold X's history. `workflow_id` answers doneness — "is run 31
finished?" = settle its workflow. Collapse them and one question breaks.
They coincide only for job-shaped facts (a workflow about exactly one
thing) — a coincidence of axes, not redundancy. ("Subject" passed the
pressure test "entity" failed: a process is a sentence's subject with no
ontological argument — `RunRequested`'s subject is the run — and the word
maps to CloudEvents' `subject` attribute, the strongest exit-path
precedent available.)

**Subject omission is shape-gated** — inference allowed only where being
wrong is impossible:

```rust
#[causal::event(name = "tick", ephemeral)]
struct TickRecorded { n: u64 }            // no Uuid fields: provably subject-less — legal

#[causal::event(name = "signal_investigated")]
struct SignalInvestigated { signal_id: Uuid }   // ambiguous: COMPILE ERROR teaching
                                                 // subject_id = "signal_id" OR no_subject

#[causal::event(name = "cache_purged", no_subject)]
struct CachePurged { requested_by: Uuid }  // ids present but they're references —
                                            // the one place the token survives
```

A fact that was legitimately subject-less re-asks the question the moment
it gains a Uuid field — loud at exactly the upgrade that could change
wire semantics. (Consequence carried in §5: subject-less facts share one
partition under `PerSubject`; high-volume subject-less feeds declare
`ORDERING::None` on their consumers.)

**Two structural rules, same shape:**
- *A fact that cannot name a single subject is two facts.*
  (`PaymentTransferred{from,to}` → `AccountDebited` + `AccountCredited` —
  the declaration's discomfort is the design pressure surfacing.)
- *A type that needs two workflow behaviors is two facts* (§3).

**One fact shape: structs. The enum form is retracted.** Enums carried a
live bug class: a family enum's trigger deserializes via serde tag, so
**adding a variant poisons every deployed consumer of the family**
(unknown variant → deser failure → terminal) — vocabulary growth as a
breaking change, the inverse of the additive-evolution rule. They also
forced routing into user code (the degenerate
`let JobEvent::Opened{..} = t else { return Ok(empty) }` match) and were
the god-enum's gravity well. Each justification dissolves: co-location →
`subject = "job"` (several fact families, one subject history — the
anti-god-enum valve; in KurrentDB this is literally the stream-name
prefix); multi-kind consumers → one consumer per kind sharing a body fn,
each with its own cursor (which is also correct); family namespace → the
subject groups storage (`$ce-job`), the module groups code. `event_type`
on the wire becomes the flat exact `name`; projector subscriptions become
explicit `kinds = [...]` lists; the macro's whole enum path (serde-tag
validation, per-variant rules) becomes deleted code.

**Retracted under pressure-test — do not re-propose:** exploding batch facts
(`CauseHeatComputed{scores: Vec<…>}`) into framework-batched per-subject
events. Attack results: (a) nothing folds per-subject heat — the split buys
fold-ability nobody asked for; (b) 200× log volume per emitter tick;
(c) per-event projector invocations unless the delivery path re-batches (new
surface); (d) 0.9 batch atomicity is **per-subject-history** — the exploded
batch can tear mid-write where the single event could not. Amended rule:
**split a batch fact only when something actually folds it per-subject;
projection-only batches stay batches on an explicit subject-less fact.**

**The coordinated rename, final form (maintainer decision; ripple
accepted — "it's worse if we get it wrong"):** the domain surface speaks
meaning; storage vocabulary survives only at the backend boundary, where
it is true and where the exit-path mapping lives (black swan #3: a
subject's history ↔ an EventStoreDB stream ↔ a Kafka keyed partition;
`subject` ↔ CloudEvents `subject`). The third pass's interim `entity`
vocabulary is superseded by this table.

| Final | Was (0.8/0.9 shipped) |
|---|---|
| macro `name = "job_opened"` | `prefix` (named string mechanics, not meaning) |
| `Event::subject_id()` / macro `subject_id = "f"` | `stream_id` |
| `Event::SUBJECT` / `Aggregate::SUBJECT` / macro `subject = "job"` | `STREAM_CATEGORY` / `stream = "job"` |
| macro `no_subject` + shape-gated omission | `nil_stream` (named the nil-uuid mechanism) |
| `workflow_id` on envelope, `EmitResult`, `Ctx`, `TerminalFailure` | `correlation_id` (tracing jargon) |
| consumer `NAME`; `TerminalFailure.consumer` | `GROUP_NAME` (Kafka vocabulary — Primitive 7) |
| `ORDERING::PerSubject` (BLOCKING-4 default) | `PerStream` |
| **Unchanged**: `EventLogBackend::read_stream` / `append_to_stream` | storage layer — where "stream" is the truth |

### 2. Determinism by construction — the deterministic `Ctx`

`react()` gets no ambient world. The `Ctx` is the only door and every door is
deterministic-or-memoized:

```rust
async fn react(&self, t: &Trigger, ctx: Ctx<'_>) -> Result<Events> {
    let id   = ctx.derive_id("group");        // v5(group ∥ trigger_id ∥ LABEL); never new_v4
    let when = ctx.time();                    // the TRIGGER's recorded time — deterministic.
                                              // (append-time created_at stays envelope-only;
                                              // wall clock must never enter a payload)
    let text = ctx.effect("ocr", || claude.ocr(&t.url)).await?;  // memoized by construction
    ...
}
```

Derivation and dedup key on **identity, not output position**. The
resilience pass found that positional keying (`derive_output_event_id` =
v5(reactor ∥ trigger ∥ index), already shipped in 0.9) is brittle across
deploys: a reactor that emits `[A, B]` today and `[A, NEW, B]` tomorrow
shifts B's index, so a redelivery straddling the deploy derives *different*
ids for the same logical outputs — B appends twice, and a workflow-root
fact re-derives a different `workflow_id`, **minting a second workflow
that nothing collides with**. The fourth pass retracted the interim fix
(user-supplied output labels) for the same reason `detach!` died: a label
restates identity the fact already carries — a second source of truth.
Output ids derive from the fact's own declarations instead:

```text
output event_id = v5( consumer NAME ∥ trigger event_id ∥ fact name ∥ subject_id ∥ n )
```

`events![]` takes a plain array. Reordering and insertion across deploys
keep every surviving output's id (keys carry no position); `n`
disambiguates only same-name-same-subject outputs within one reaction —
the one place position is semantically honest (insertion IS a new item).
`ctx.derive_id(label)` keeps its label argument: it *mints* a new
identity, so there is genuinely nothing else to derive from.

Four load-bearing details from the pressure tests:

- **Effect-cache GC is bound to the ack floor — except through the
  failure store.** Effect results (full LLM extractions, fetched pages) are
  large, but they exist only to make *redelivery* deterministic — once the
  checkpoint floor passes the trigger, the entry is dead. GC by floor or
  the cache grows to the size of the log. The exception the resilience
  pass found: **failure replay happens after the floor has passed**, so
  parking a trigger as a terminal failure must snapshot its effect entries
  into the failure row, and replay restores them.
  Otherwise the operator's replay re-runs effects fresh, the nondeterministic
  outputs diverge against any partially-appended originals, and the replay
  path — used under stress, after an incident — poisons itself by default.
- **Duplicate `derive_id`/`effect` labels in one react are a runtime
  error.** `derive_id("group")` called twice in one invocation silently
  yields the same id — a silent-correctness bug. The runner tracks labels
  per invocation and errors (domain class) on reuse. (Same rule, derived
  rather than tracked, for outputs: two same-name outputs about the same
  subject in one reaction take ordinals — see the derivation above.)
- **The divergence error prints the first differing JSON path** (e.g.
  `outputs[2].candidates[0].signal_id`), not just "payload differs" — the
  producer's nondeterminism is usually in a dependency crate far from the
  reactor, and the path is the difference between a grep and a debugging
  session.
- **Canonicalization cannot see through pre-serialized payloads.** Framework
  sorting of map keys fixes `HashMap` fields; it cannot fix a `String` field
  containing `serde_json::to_string(&hashmap)` done in user code. Doc rule:
  payloads carry structured data, never embedded JSON strings.
- **Projection queries are effects.** Reads against derived read models
  (Neo4j similarity search, "hottest ungrouped") are nondeterministic under
  redelivery *by construction* — the 0.9 divergence check will flag them
  today whenever a crash-redelivery straddles a projection write, independent
  of this design. They go under `ctx.effect` like any external call; results
  (ids + scores) are small. The honest read rule: **in-reactor reads are
  subject folds (free, deterministic) or memoized queries (effects).**
  "Folds, full stop" was overclaim.
- **Rust cannot make nondeterminism inexpressible** — no effect system;
  nothing *stops* `Uuid::new_v4()` inside `react()`. Three layers, none
  sufficient alone: the deterministic `Ctx` is the paved road; a clippy
  `disallowed-methods` lint (`Uuid::new_v4`, `Utc::now`, raw HTTP clients, in
  reactor modules) is the guardrail; the runtime divergence check is the
  backstop. Payload canonicalization (structural comparison / sorted map
  serialization) lives in the framework so `HashMap` iteration order can
  never manufacture divergence.

### 3. Workflow roots are declared on the fact — `detach!` retracted

**Retracted under maintainer review — do not re-propose:** the `detach!`
emit-site macro and `ctx.derive_correlation`. The attack that killed it:
an execution instruction riding inside a fact list is a command in fact
clothing; the macro created two sources of truth for one identity (its
own spec carried a clause keeping payload and envelope from disagreeing —
a design apologizing for itself); and per-site choice let one fact type
mean different things at different call sites. **Events are
fire-and-forget, all of them, uniformly** — nothing at an emit site may
carry execution semantics.

The replacement: **which workflow a fact belongs to is part of what the
fact IS**, declared where its subject is declared:

```rust
// Chain member (the default): no declaration — inherits the trigger's workflow.
#[causal::event(name = "signal_corroborated", subject = "signal", subject_id = "signal_id")]
struct SignalCorroborated { signal_id: Uuid, run_id: Uuid, occurred_at: DateTime<Utc> }

// Workflow ROOT: this fact's workflow is named BY its own field —
// constitutionally, at every emit site, from any emitter.
#[causal::event(name = "job_opened", subject = "job", subject_id = "job_id",
                workflow_id = "job_id")]
struct JobOpened { job_id: Uuid, file_id: Uuid, occurred_at: DateTime<Utc> }
```

In-chain outputs remain decisions: fast, settle-waited, ordered. Slow
external labor gets a workflow-root fact: its own lifecycle, its own
settle scope, outside the parent's. The contract, all of it:

- **One source of truth.** The envelope `workflow_id` is stamped FROM the
  payload field (macro-generated accessor — the same machinery as
  `subject_id`). Payload and envelope cannot disagree; the 0.8 hardcode
  (`reactor_runner.rs:560`, outputs always inherit) is deleted rather
  than escaped.
- **Conflict is loud.** `.workflow_id(x)` on the emit builder against a
  type that declares its own is an error, never a silent precedence.
- **The declaration cannot save a nondeterministic field.** The value
  must be derived (`ctx.derive_id`) — a `new_v4()` workflow id mints a
  phantom workflow on redelivery; the divergence check catches it as
  poison, loudly, but it is still a bug. Same discipline as every other
  identity.
- **Constitutional rigidity is the point.** A fact type is a chain
  member or a workflow root — never per-call-site. A type that "needs
  both" is two facts wearing one name; the declaration forces the split.
- **A capability `detach!` never had:** the field may carry an EXISTING
  workflow's id — the named-mailbox / actor-send pattern: a fact that
  joins another live workflow's partition, ordering, and settle scope.
  Caveat carried with it: the field value decides whose settle you join,
  so the derivation at the emit site is what reviewers review.
- **`settle_tree` is test/ops-only, and the docs say so loudly.**
  Causation links cross workflow boundaries, so the transitive wait
  stays discoverable for test harnesses awaiting full pipelines.
  Production code reaching for it to await a slow child locally rebuilds
  the settle-hostage problem — needing a child's result is a *reaction
  to the child's completion fact*, not a wait.
- **Cancellation does not propagate across workflow roots by default.**
  Right for work that outlives its parent (file enrichment outlives the
  run that archived the file). The choice is per-TYPE, like everything
  else about the fact (residual #7).

**Boundary handles** complete the picture: genuinely exogenous signals
(clock ticks, HTTP mutations, webhook callbacks) enter via
`engine.boundary("due_sweep").emit(..)` — a named handle stamping origin
attribution into the envelope. Workflow-root declarations pay double at
the boundary: `RunRequested` declares `workflow_id = "run_id"`, so a run
emitted from GraphQL, an ops tool, or the flywheel roots the same
workflow the same way — no builder discipline at any of them. A healthy
downstream app has very few boundaries (rootsignal post-migration: the
due-sweep clock and the GraphQL mutations — two).

### 4. Reads are subject folds or memoized queries — nothing else

One verb; the receiver is the consistency:

```rust
ctx.state_of::<JobState>(id).await      // in a body: state AS OF YOUR TRIGGER (prev/curr)
engine.state_of::<JobState>(id).await   // outside: durable, current
```

There is no third way to read state. The fourth pass **deleted**
`engine.snapshot()` (the sync racy peek whose documentation was a
paragraph of "do not use this for decisions" — a name's job done by
apologies) and, with it, **the eagerly-folded engine registry it was the
sole consumer of** — which also deletes the fold-on-every-emit overhead
and the subsystem the vacant-restore TOCTOU lived in, and dissolves the
`snapshot`/`SnapshotStore` name collision (`SnapshotStore` keeps its name:
it stores literal fold snapshots accelerating `state_of`). Fan-in `id_fn`
aggregates die with that registry — they were already banned from
decisions, and cross-subject analysis is replay tooling
(`causal_replay`), not an engine read API.

`state_of` is subject-aligned, enforced loudly at registration
(`A::SUBJECT` must match; the error teaches: "say which subject these
facts are about — set `subject_id` to the id you fold by"). The no-arg
singleton is gone. Registration must permit **multiple aggregates per
subject** (two lifecycle aggregates folding different fact kinds of the
same subject histories is legitimate — the check is subject match + fold
determinism, not one-aggregate-per-subject).

### 5. Liveness defaults flipped

- Terminal-failure path mandatory: either a mapper registered via
  `on_terminal_failure(mapper, attempts)` or the built-in terminal fact
  (`causal:reaction_failed { consumer, trigger_id, class, error }`,
  carrying the trigger's workflow and subject identity so completion folds
  can see it — see BLOCKING-2). The mapper receives
  `TerminalFailure { consumer, trigger_id, subject, subject_id,
  workflow_id, class, attempts, error }` — the audit found the old
  `DlqInfo` lacked the subject identity the BLOCKING-2 contract requires
  the mapper to stamp.
- Retry per the ⛔ BLOCKING-2 taxonomy — no blanket policy in either
  direction.
- Partition-isolated failure (0.9) + the BLOCKING-3 pending-work window.
- **Partitions are evicted when drained** (recreated on the next matching
  event). Without explicit retirement the partition map grows monotonically
  with workflow count — a slow leak, found by the resilience pass, that
  no test catches because tests never run a million workflows.
- No infinite-block-retry *mode*; transient-class backoff is the sanctioned
  "wait out the outage" behavior.
- **Projector `kinds` lists are settle-latency surfaces.** Settle correctly
  waits on projector cursors (an unfolded read model isn't settled), which
  means a projector that subscribes to a fact kind silently couples every
  workflow emitting that kind to its write latency. Subscribing broadly is
  a settle decision, not just a routing one — docs carry this; the
  registration log line prints the kinds list for the same reason.
- **Subject-less facts share one partition** under `PerSubject` ordering;
  a high-volume subject-less feed declares `ORDERING::None` on its
  consumer (Primitive 1's omission rule carries this consequence).

### 6. The engine owns two clocks, and they never cross

**Calendar time** is injected (`Engine::new(.., clock)`): every timestamp
the framework stamps (`created_at`, failure-record times) comes from it;
tests inject a fixed clock and `created_at` becomes reproducible. Stated
precisely: **replay is byte-stable only when all three hold** — injected
clock, effects memoized, canonical payload serialization. Any one alone
is not the property.

**Liveness time** is tokio time: every framework wait and every duration
comparison — settle polls, supervisor backoff, the BLOCKING-2 transient
ceiling, `settled().within()`, partition eviction, the BLOCKING-3 window
— runs on `tokio::time` primitives, which virtualize under
`#[tokio::test(start_paused = true)]`. The test-suite pass verified the
current code keeps waits on tokio sleeps (engine.rs 1233/1614/1650/1661);
the property to hold is the rule, stated as a design invariant:
**chrono never participates in a liveness decision.** Wall-clock in a
wait or ceiling would make the liveness surface testable only in
production — a lying default about testability. With the split, "back off
through a 10-minute outage, then park as `transient_exhausted`" is a
millisecond-scale paused-time test.

### 7. Consumers are functions — the macro surface

History first: a `#[reactor]` macro existed and was **deleted in the
2026-06-10 audit** (it generated calls to dead APIs and had zero users).
This is its revival with the lessons applied: the macro removes trait
ceremony only — it is forbidden from deciding anything load-bearing.

```rust
#[causal::reactors(deps = JobDeps)]
mod job_reactors {
    pub struct JobDeps { pub cfg: EnrichmentConfig, pub whisper: Arc<WhisperClient> }

    #[reactor(name = "job.enrich", max_in_flight = 4)]    // knobs in the diff
    async fn enrich(deps: &JobDeps, t: &EnrichmentJobOpened, ctx: Ctx<'_>) -> Result<Events> {
        …                                                  // the Primitive-2 body, untouched
    }
}
// EngineBuilder: .with_reactors(job_reactors::reactors(JobDeps { … }))
```

Expansion contract: each fn becomes the hand-written struct + `Reactor`
impl, verbatim — trigger type read from the fn signature, attribute values
copied into the consts, deps captured in the generated struct, the fn body
called untouched. `#[projectors(deps = …)]` is the same shape for
projectors/multi-projectors. `#[aggregators]`/`#[aggregator]` (which
already exist) complete the set: folds, decisions, and projections are all
plain functions; modules register in bulk; `main` stops enumerating
structs.

The rule that makes the macro safe — **inference is allowed only where
wrong inference fails loudly**:

| Inferred (wrongness is loud) | Required explicit (wrongness is silent) |
|---|---|
| `Trigger` from the fn's parameter type — a wrong type changes which events arrive, visibly | `name` — it names a **durable cursor**; a fn-name-derived default turns a rename refactor into an orphaned cursor: reactors reseed at latest (backlog silently skipped), projectors reseed at zero (full re-projection into live read models) |
| Deps threading from the module's `deps =` struct | `kinds` on projectors — each entry is a settle-latency coupling (§5) |
| The registration list (`reactors()`, `projectors()`) | Every execution-semantics knob: `max_in_flight`, `ordering` (BLOCKING-4's per-reactor declaration rides this attribute) — concurrency belongs in the same diff as the body it governs |

If fn-derived names are ever wanted, the price is making the rename
hazard loud instead of silent: `build()` enumerates persisted cursors and
errors when a registered consumer has no cursor while an unclaimed one
exists ("renamed? set `name` explicitly or migrate the cursor") — which
requires a cursor-listing API plus a consumer-retirement story for
deliberate removals. Until someone pays for that machinery, explicit
`name` is one line and it doubles as the ops identity (DLQ rows,
checkpoint tables, inspector) that runbooks grep for.

**Rename, part of this primitive: `GROUP_NAME` → `NAME` everywhere**
(`Reactor`/`Projector`/`MultiProjector` consts, `DlqInfo.group_name` →
`consumer`, `reaction_failed.group` → `consumer`, the v5 derivation
recipes read "consumer name"). "Group" is Kafka/ESDB vocabulary for
N competing instances sharing a cursor — a feature causal explicitly
does not have (single-engine boundary; leases are residual #6). The
runtime already calls this value `consumer_id` internally; the lie
exists only at the trait surface. `Aggregate::NAME` is the in-house
precedent, including its "treat it like a wire format" contract. If
leases ever land, instances join a `NAME` — the rename never reverts.

## The API audit (fourth pass) — rulings

An exhaustive end-state listing of every user-facing surface was written
and read as one artifact; six inconsistencies fell out. Rulings, all
maintainer-decided, all riding sequencing step 1:

1. **One registration method.** `with_aggregators(folds::aggregators())`
   is the only state registration. The OCC fence stops being a builder
   call (`with_aggregate` — confusably named, semantically enormous) and
   becomes a property of the state that owns the invariant:
   `Aggregate::INVARIANT: bool = true` ⇒ that aggregate's fact kinds are
   emit-fenced, reactor-fenced (C4), and writable only through
   `Engine::append`. Wiring carries no semantics; declarations do.
2. **`with_effect_store`** (was `with_reaction_cache`) — the builder
   speaks the same language as `ctx.effect`.
3. **`on_terminal_failure(mapper, attempts)`** (was `on_dlq`);
   `TerminalFailure` replaces `DlqInfo` and gains the trigger's subject
   identity (see Primitive 5). "DLQ"/"dead-letter" leave the vocabulary:
   the concept is *terminal failure*, the parked rows are the *failure
   store*.
4. **The read duo** — `ctx.state_of` / `engine.state_of`;
   `engine.snapshot()` and the eager engine registry deleted (see
   Primitive 4 for the dividend list).
5. **Label-free `events!`** — output dedup derives from (consumer NAME ∥
   trigger ∥ fact name ∥ subject_id ∥ n); see Primitive 2.
6. **Structs-only facts** — the enum form retracted; see Primitive 1.

## The test-suite pass (fifth) — consumer asks, ruled

A consumer read ("does 0.10 give a test suite what it needs") confirmed
`settle_tree`, the determinism triple, `ctx.effect`-transparent mocks, the
events-first testability of the retry taxonomy, and the `state_of`
cleanup. Three asks and one upgrade, all accepted:

1. **Virtual time governs durations** — Primitive 6's two-clock rule (the
   load-bearing ask; verified against current code).
2. **The ordering contract is declared, not engineered around.** Under the
   partitioned runner, cross-subject capture order is nondeterministic by
   design. The contract, owned loudly by the docs and the test helpers:
   **assert on state and on per-subject order; cross-subject order is
   undefined** — quiescence points (`settled`, `settle_tree`) make state
   assertions deterministic, and captured-log helpers expose per-subject
   views. A deterministic serial test scheduler was considered and
   **rejected**: tests would validate a scheduler production never runs —
   a lying default for tests.
3. **The failure store and effect store are first-class READ surfaces**
   (all backends, MemoryStore included): list/get parked terminal
   failures with class, attempts, and attached effect entries. The
   resilience-pass guarantee ("replay restores effect entries") is
   otherwise unverifiable — a guarantee that cannot be observed is a
   rumor.
4. **Checkpoint/reactor-cursor conformance gates the release** (upgraded
   from action item): warm-restart tests trust MemoryStore checkpoints,
   and that trust is currently unverified by the conformance suite.

## Black swans — structural commitments that could force a whole-codebase refactor

Distinct from residuals: residuals are operational failures with bounded
blast radius; these are *organizational* decisions that are cheap now and
catastrophic to change after code accretes around them.

1. **The partition key (BLOCKING-4).** Live now; decided by memo before the
   runner lands or discovered by refactor later. The only entry on this list
   with a deadline.
2. **Fat events.** Facts are forever; every future fold carries legacy arms
   for every historical payload shape. Data-truck events (full extraction
   batches, page previews in payloads) make the *next domain remodel* an
   event-schema migration. Rule, decided now: **facts are thin** — ids,
   decisions, small measurements; bulk data lives in the archive/blob layer,
   referenced by id. Vocabulary policy: new variants append; old variants
   are never reinterpreted; folds keep legacy arms. Schema evolution is
   additive by construction, which is why upcasters stay un-built.
3. **Bespoke-framework lock-in.** Everything downstream couples to a
   framework one person maintains. Mitigation is a stated design constraint,
   checked in review: **every causal concept maps to an industry primitive
   with an exit path** — subject histories ↔ EventStoreDB streams,
   partition semantics ↔ Kafka, determinism rules ↔ Temporal workflows,
   `effect` ↔ activities, `subject`/`name` ↔ CloudEvents `subject`/`type`
   (the neutral export is near-CloudEvents-shaped for free). A proposed
   feature with no analog is the red flag.
4. **Settle as a public promise.** Every caller that awaits `settled()` then
   reads is a caller that cannot survive settle-latency growth without UX
   redesign. Discipline: mutations may settle; everything else reacts to
   completion facts.

5. **(rootsignal) The graph is secretly two databases — only one survives
   replay.** "Neo4j is a derived projection" is false today: five live write
   paths put *authoritative* curator/ops state into the graph with no event
   behind them — region creation (`region_watching.rs:427`), source creation
   (`source_tracking.rs:211`), tier locks (`admin/mutations.rs:1256`),
   investigation source-deactivation (`investigations/tools.rs:814`),
   situation temperature/embedding updates. Nuke-and-replay — the standing
   rebuild story, used before — silently loses all of it, discovered during
   a rebuild. Every curator feature deepens the gap. Fix = Primitive 3
   applied: curator actions are facts (`SourceAdded`, `RegionWatched`,
   `SourceTierLocked`, `SourceDeactivated`) via boundary handles. (This also
   corrects an earlier claim: mutations were never "two boundaries" — they
   are many boundary emissions, currently bypassing the log.)
6. **(rootsignal) Embedding vectors carry no model version.**
   `voyage-3-large` hardcoded twice (scout const + raw strings in
   `api/kernel/graph_projection.rs:254,327`); vectors stored in Neo4j
   properties, vector indexes, AND event payloads
   (`SituationIdentified.narrative_embedding`) — none stamped. Only the pg
   `embedding_cache` tracks `model_version`. A model change produces
   silently mixed-generation vectors: dedup compares incomparables,
   similarity edges go half-stale unauditable, coalescing clusters on
   garbage. Fix while cheap: one const; `embedding_model` stamped beside
   every stored vector and in events; mismatch = cache-miss recompute. Fix
   the known B2 bug (queries reference pre-rename index names
   `aid_embedding`/`need_embedding` absent on clean projection —
   `writer.rs:121`, `reader.rs:740`) in the same pass.
7. **(rootsignal) ID-permanence is inconsistent per entity** — groups:
   tombstone + `merged_into` redirect but deep links 404; situations:
   status-gated stub (best-in-class); locations: ids physically destroyed
   (safe only while unexposed); signals: nothing. Latent replay bug:
   `GroupCreated` projector arm lacks the resurrection guard
   `SituationIdentified` has (`projector.rs:3135` vs `:1756`) — replayed
   creation can resurrect a merged-away group. Rule: ids are permanent
   names; merge = tombstone + redirect; every `*Created` projector arm
   carries a resurrection guard; signal-merge inherits this contract.

**Swept and clean — backend semantic parity (causal).** Expected
"MemoryStore-tested, Kurrent-divergent"; found a 19-scenario conformance
suite (`causal_replay/src/conformance.rs`) run identically against
Memory/Postgres/Kurrent (dedup, divergence rejection, batch atomicity,
position monotonicity, concurrent appends), with live backends in CI via
docker compose. Two items: flip the live job from
`continue-on-error: true` to gating once burned in; extend conformance to
the checkpoint/reactor-cursor stores — the latter upgraded to a
**release gate** by the test-suite pass (its warm-restart trust rests on
it).

### Framework mechanisms — converting these from discipline into properties

Discipline rules are lying defaults too. Each swan gets a mechanism that

| Swan | Mechanism |
|---|---|
| 1. Partition key | **Declared ordering** (`const ORDERING` per reactor, default `PerSubject`) — the global key stops existing; see BLOCKING-4's recommendation |
| 2. Fat events | **Append-time payload budget** (warn/hard ceiling at emit; `extracted_batches` trips it on day one) + **`causal::BlobRef`** as the blessed bulk-data escape + **`vocab_check!` CI gate** (round-trip every historically appended `event_type` through current deserializers — a removed variant fails CI, not production; this is why upcasters stay un-built) |
