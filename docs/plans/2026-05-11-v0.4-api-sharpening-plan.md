# v0.4.0 API sharpening

## Overview

A breaking release that sharpens the public API by deleting everything that
doesn't earn its weight and aligning the remaining surface with KurrentDB's
native vocabulary. Net effect: ~1/3 fewer public entities, names match the
field standard, every concept maps one-to-one to a Kurrent primitive.

The implementation is heavy in line count (Phase 9 legacy collapse + a
dozen renames) but the design is locked. Every decision below has been
pressure-tested; no open questions remain.

## Motivation

The audit revealed three classes of waste:

1. **Method splits that don't earn weight.** `emit` / `emit_in`,
   `append` / `append_in`, `Ctx::aggregate` / `Ctx::aggregate_of`,
   `with_aggregate` / `with_aggregators` — pairs that solve the same
   problem twice, with the split serving as a documentation hint that
   the type system could enforce or that a builder could absorb.
2. **Invented vocabulary that doesn't map to event sourcing.**
   `type_prefix`, `NAMESPACE`, `entity` — concepts causal-rs introduced
   that have no equivalent in Kurrent, EventStoreDB, Marten, or Axon.
   Forces consumers to learn library-specific terms instead of field-
   standard ones; makes the Kurrent backend (planned) harder to write.
3. **Legacy carryover from the v0.2 → v0.3 transition.** Six trait
   pairs (`Aggregate`/`aggregate_v3::Aggregate`, etc.) and ~10 dead
   types/methods existing solely to keep the legacy engine compiling
   alongside v0.3. v0.3 has landed; the legacy can go.

This release closes all three.

## Design decisions

Locked. Each decision is named with a Dn identifier for cross-reference
in the implementation PRs.

### D1: Single `emit` method with `.expecting()` builder

Collapse `emit` + `emit_in` + `append` + `append_in` into one
`Engine::emit` method. CAS opt-in via `.expecting(version)` builder.
Envelope propagation removed entirely — reactors don't call `emit`
(they return `Events`), so the `in_context` builder solves a problem
that doesn't exist.

```rust
engine.emit(fact).await?;                     // no CAS, boundary use
engine.emit(fact).expecting(version).await?;  // CAS for aggregate streams
engine.emit(vec![f1, f2]).expecting(v).await?; // batch
```

`engine.emit` is **boundary-only**. Called by ingestion gateways (HTTP
handlers, CLI commands), tests, and migration scripts. Never from
inside a reactor body — reactors return `Events`, the runtime emits
internally with envelope propagation handled automatically.

Aggregate-OCC streams reject `emit` without `.expecting(v)` (preserves
the C11 contract — aggregate streams require CAS).

### D2: Fact uses Kurrent-native vocabulary

Drop `type_prefix` and `type_name`. Use Kurrent's `category` + `event_type`
+ stream id.

```rust
pub trait Fact: Serialize + DeserializeOwned + Send + Sync + 'static {
    /// Stream category — the prefix Kurrent's `$by_category` extracts
    /// from stream names of the form `{category}-{id}`. Identifies the
    /// kind of entity this fact is about. All variants of a Fact enum
    /// share one category.
    const CATEGORY: &'static str;

    /// Event type (Kurrent: the `event_type` string stored per event).
    /// Per-variant. The runtime composes the stored event_type as
    /// `format!("{}:{}", Self::CATEGORY, self.name())` so the log is
    /// self-describing without requiring callers to repeat the
    /// category prefix in every variant.
    fn name(&self) -> &str;

    /// Which stream within the category this fact targets. Combined
    /// with CATEGORY, the runtime produces the full Kurrent-style
    /// stream name `{CATEGORY}-{stream_id}`.
    fn stream_id(&self) -> Uuid;

    /// Producer-claimed time. Defaults to None (runtime uses log
    /// append time). Override only when the fact carries backdated or
    /// external time (migration imports, third-party feeds).
    fn occurred_at(&self) -> Option<DateTime<Utc>> { None }
}
```

No `StreamRef` struct — the runtime constructs the stream name from
`CATEGORY` + `stream_id()`. No separate `NAMESPACE`, `type_prefix`, or
`entity` concept. One string axis (`CATEGORY`) for both subscription
identity and stream identity.

### D3: Aggregate inherits its category from Fact

```rust
pub trait Aggregate: Default + Send + Sync + 'static {
    type Fact: Fact;
    fn apply(&mut self, fact: &Self::Fact);
}
```

Two members. The category comes from the associated `Fact::CATEGORY` —
no separate `Aggregate::CATEGORY` const. Engine ops use the trait:

```rust
engine.load::<Schedule>(id) {
    let category = <Schedule as Aggregate>::Fact::CATEGORY;
    let stream = format!("{}-{}", category, id);
    /* load + fold */
}
```

The aggregate IS the v3 read-side fold AND the write-side OCC marker —
both responsibilities derive from one trait + one Fact category. No
`with_aggregate<A>` singular method (see D5).

### D4: Projector replaces Materializer (field-standard name)

```rust
pub trait Projector: Send + Sync {
    type Fact: Fact;
    const GROUP_NAME: &'static str;
    async fn project(&self, fact: &Self::Fact, ctx: Ctx<'_>) -> Result<()>;
}

pub trait MultiProjector: Send + Sync {
    const CATEGORIES: &'static [&'static str];
    const GROUP_NAME: &'static str;
    async fn project(&self, event: &PersistedEvent, ctx: Ctx<'_>) -> Result<()>;
}
```

Rename rationale:
- "Projection" is the field-standard term (Marten, EventStoreDB, Axon).
- "Projector" describes the *what* (a derived read model writer),
  whereas "Materializer" described the *how* (the act of materializing).
- The codebase already mixed both — `Materializer` in the trait,
  `GraphProjector` in user impl names. Aligning on one term.

`MultiPrefixMaterializer` → `MultiProjector` (drop "Prefix" too — it
referenced an internal `TYPE_PREFIXES` const that's being replaced with
`CATEGORIES` per D2).

### D5: One `with_aggregators` method, variadic + chainable

```rust
EngineBuilder::new(log, checkpoint, outbox)
    .with_aggregators([
        Aggregator::for_type::<Schedule>(),
        Aggregator::for_type::<PipelineState>(),
    ])
    .with_aggregators(my_module::aggregators())  // chainable
    /* ... */
    .build()
```

Drop `with_aggregate<A>` (singular). The plural form is variadic via
`IntoIterator<Item = Aggregator>`; single-aggregate users wrap in
`[...]`. Each call accumulates onto the same set. Registration handles
**both** the write-side OCC marker AND the read-side fold registration —
not two separate concerns, two facets of the same trait impl.

### D6: GROUP_NAME on consumer traits, not on registration calls

Move the persistent-subscription identifier from the `with_*` call to
a trait const:

```rust
// Before:
builder.with_materializer(SchedulesMaterializer::new(pool), "schedules");
//                                                          ^^^^^^^^^^^ opaque

// After:
impl Projector for SchedulesProjector {
    type Fact = SchedulingEvent;
    const GROUP_NAME: &'static str = "schedules";
    /* ... */
}
builder.with_projector(SchedulesProjector::new(pool));
//                                                  ^ no opaque second param
```

Rationale: the durable identifier should live next to the body it
identifies, not at the registration call site. The struct name can be
refactored freely; the GROUP_NAME is the stable contract that survives
renames. Matches Kurrent's `create_persistent_subscription_to_stream`
parameter name (`group_name`) directly.

If a consumer ever needs to be registered under multiple group names
(sharding pattern), add an override-taking `with_projector_as(id, group)`
later. The 99% case is one consumer = one group, and the trait const
captures that cleanly.

### D7: Both `aggregate()` and `aggregate_of(id)` on Ctx

Conceded during review. Singletons via `aggregate()` (no id), keyed via
`aggregate_of(id)`. Forcing `aggregate(Uuid::nil())` was hostile DX.

```rust
let state = ctx.aggregate::<PipelineState>();     // singleton
let order = ctx.aggregate_of::<Order>(order_id);  // keyed
```

### D8: `ProjectionStore` → `CheckpointStore` (required) + `ProjectionOps` (optional)

Invert the trait hierarchy. Today: `ProjectionStore` is the rich
required trait, `CheckpointStore` is auto-impl via blanket. Result:
backends must implement 12 methods even when no runner consumes the
extras.

After:

```rust
// REQUIRED. Two methods. Every runner depends on this.
pub trait CheckpointStore: Send + Sync {
    async fn get(&self, group_name: &str) -> Result<Option<LogCursor>>;
    async fn set(&self, group_name: &str, pos: LogCursor) -> Result<()>;
}

// OPTIONAL extension. Backends with DLQ + pause/resume infrastructure
// implement; backends without don't. Engine ops methods that need this
// surface are only available when the backend implements it.
pub trait ProjectionOps: CheckpointStore {
    async fn set_paused(&self, group_name: &str, paused: bool) -> Result<()>;
    async fn record_failure(&self, group_name: &str, event_id: Uuid, error: &str, attempts: u32) -> Result<()>;
    async fn list_failures(&self, group_name: &str, limit: usize) -> Result<Vec<ProjectionFailure>>;
    async fn status(&self, group_name: &str) -> Result<Option<ProjectionStatus>>;
    async fn delete_failure(&self, group_name: &str, event_id: Uuid) -> Result<bool>;
}
```

`ProjectionStore` is deleted. The 35 conformance tests are split: the
get/set tests run against `CheckpointStore` (every backend); the DLQ /
ops tests run against `ProjectionOps` (only backends that implement
it).

### D9: Top-level prelude trimmed

Today's `lib.rs` has 30+ `pub use` lines including implementation
details (`OutboxRow`, `derive_output_event_id`, `NS_REACTOR_OUTPUT`,
`StepOutcome`, internal runner types). v0.4 prelude is ~20 items.
Everything else moves behind module paths. Implementation details that
consumers occasionally need stay accessible via `causal::module::Thing`
but don't pollute the prelude.

## DX walkthrough — end-to-end

```rust
// ── Define a fact ────────────────────────────────────────────────

#[derive(Debug, Clone, Serialize, Deserialize)]
pub enum SchedulingEvent {
    ScheduleCreated { schedule_id: Uuid, next_run_at: DateTime<Utc> /* ... */ },
    ScheduleTriggered { schedule_id: Uuid, run_id: Uuid, next_run_at: DateTime<Utc> },
    ScheduleDeleted { schedule_id: Uuid, deleted_at: DateTime<Utc> },
}

impl Fact for SchedulingEvent {
    const CATEGORY: &'static str = "schedule";
    fn name(&self) -> &str {
        match self {
            Self::ScheduleCreated { .. }   => "schedule_created",
            Self::ScheduleTriggered { .. } => "schedule_triggered",
            Self::ScheduleDeleted { .. }   => "schedule_deleted",
        }
    }
    fn stream_id(&self) -> Uuid {
        match self {
            Self::ScheduleCreated { schedule_id, .. }
            | Self::ScheduleTriggered { schedule_id, .. }
            | Self::ScheduleDeleted { schedule_id, .. } => *schedule_id,
        }
    }
}

// ── Define an aggregate ──────────────────────────────────────────

#[derive(Default, Clone)]
pub struct Schedule {
    pub next_run_at: Option<DateTime<Utc>>,
    pub deleted: bool,
}

impl Aggregate for Schedule {
    type Fact = SchedulingEvent;
    fn apply(&mut self, fact: &SchedulingEvent) {
        match fact {
            SchedulingEvent::ScheduleCreated { next_run_at, .. }
            | SchedulingEvent::ScheduleTriggered { next_run_at, .. } => {
                self.next_run_at = Some(*next_run_at);
            }
            SchedulingEvent::ScheduleDeleted { .. } => {
                self.deleted = true;
                self.next_run_at = None;
            }
        }
    }
}

// ── Define a projector ───────────────────────────────────────────

pub struct SchedulesProjector { pool: PgPool }

#[async_trait]
impl Projector for SchedulesProjector {
    type Fact = SchedulingEvent;
    const GROUP_NAME: &'static str = "schedules";

    async fn project(&self, fact: &SchedulingEvent, ctx: Ctx<'_>) -> Result<()> {
        match fact {
            SchedulingEvent::ScheduleCreated { schedule_id, next_run_at, .. } => {
                sqlx::query(/* ... */)
                    .bind(schedule_id).bind(next_run_at).bind(ctx.occurred_at)
                    .execute(&self.pool).await?;
            }
            /* ... other variants ... */
        }
        Ok(())
    }
}

// ── Define a reactor ─────────────────────────────────────────────

pub struct RunCompletion;

#[async_trait]
impl Reactor for RunCompletion {
    type Trigger = LifecycleEvent;
    const GROUP_NAME: &'static str = "run_completion";

    async fn react(&self, trigger: &LifecycleEvent, ctx: Ctx<'_>) -> Result<Events> {
        let LifecycleEvent::PhaseCompleted { run_id, .. } = trigger else {
            return Ok(Events::new());
        };
        let state = ctx.aggregate::<PipelineState>().curr;
        Ok(events![LifecycleEvent::ScoutRunCompleted {
            run_id: *run_id,
            finished_at: ctx.now(),
            stats: state.stats.clone(),
        }])
    }
}

// ── Wire the engine ──────────────────────────────────────────────

pub fn build_engine(pool: PgPool) -> Engine {
    let log: Arc<dyn EventLogBackend> = Arc::new(PgEventLogBackend::new(pool.clone()));
    let outbox_arc = Arc::new(PgReactorOutbox::new(pool.clone()));
    let checkpoint: Arc<dyn CheckpointStore> = outbox_arc.clone();
    let outbox: Arc<dyn ReactorOutbox> = outbox_arc;

    EngineBuilder::new(log, checkpoint, outbox)
        .with_aggregators([
            Aggregator::for_type::<Schedule>(),
            Aggregator::for_type::<PipelineState>(),
        ])
        .with_projector(SchedulesProjector::new(pool.clone()))
        .with_projector(RunsProjector::new(pool.clone()))
        .with_multi_projector(GraphProjector::new())
        .with_reactor(RunCompletion)
        .build()
}

// ── Boundary write path (HTTP handlers, CLI commands) ────────────

// Root event (no envelope to propagate, fresh correlation_id):
engine.emit(SchedulingEvent::ScheduleCreated { /* ... */ }).await?;

// Command handler with CAS:
let (schedule, version) = engine.load::<Schedule>(schedule_id).await?;
if schedule.deleted { return Err(anyhow!("schedule is deleted")); }
engine.emit(SchedulingEvent::ScheduleTriggered { /* ... */ })
    .expecting(version)
    .await?;

// Batch (multiple facts to same aggregate, one CAS):
engine.emit(vec![
    SchedulingEvent::ScheduleTriggered { /* ... */ },
    SchedulingEvent::ScheduleCadenceAdjusted { /* ... */ },
]).expecting(version).await?;
```

## Migration table — rootsignal-scout

Concrete changes per file. All mechanical; bodies unchanged.

| File / Site | Change |
|---|---|
| `*_materializer.rs` × 5 — trait impl headers | `impl Materializer for X` → `impl Projector for X`. Method name `materialize` → `project`. Add `const GROUP_NAME` from registration call site. |
| `*_reactor.rs` × 7 — trait impl headers | `use causal::reactor_v3::Reactor` → `use causal::Reactor`. Add `const GROUP_NAME` from registration call site. |
| `core/aggregate.rs` (and aggregator definitions) | `impl Aggregate for X` — drop `const CATEGORY` (inherited from `Fact::CATEGORY`). |
| `domains/*/events.rs` — Fact impls | `type_prefix()` → `const CATEGORY`. `type_name()` → `name()` (return just the variant name, not `"prefix:variant"`). `stream() -> StreamRef` → `stream_id() -> Uuid`. Resolve any namespace/category mismatch (e.g., rename "scheduling" → "schedule" for SchedulingEvent if its variants target category="schedule"). |
| `core/v03_engine.rs` — builder calls | `with_aggregate::<X>()` calls collapse into one `with_aggregators([...])`. `with_materializer(impl, "id")` → `with_projector(impl)` (id moves to trait const). `with_multi_prefix_materializer` → `with_multi_projector`. |
| Any `Ctx::aggregate_of(id)` call | Unchanged — both methods kept (D7). |
| Any `ctx.aggregate::<X>()` call | Unchanged — singleton accessor kept. |
| Any `engine.append::<A>(id, ver, vec![f])` | → `engine.emit(f).expecting(ver).await?`. |
| Any `engine.emit_in(f, opts)` | → `engine.emit(f).await?` (and stop propagating envelope — reactors return Events, ingestion handlers don't propagate). |
| Cursor tracking under deleted names | None — `GROUP_NAME` per consumer matches what was passed as the registration id today, so existing cursors resume cleanly. |

Estimated rootsignal LOC touched: ~200-400 lines, almost entirely
mechanical. Bodies (the SQL writes, the business logic) unchanged.

## Implementation phases

Phases ordered so each phase is independently shippable and the engine
keeps compiling throughout.

**P1 (1 day): Fact rework.** Replace `type_name`/`type_prefix`/
`StreamRef` with `CATEGORY` const + `name()` + `stream_id()`. Update
all backend code that reads the stream identifier. Update macros to
generate the new shape.

**P2 (1 day): Aggregate simplification.** Drop `Aggregate::CATEGORY`
const (inherited from `Fact::CATEGORY`). Update `Engine::load<A>` and
`with_aggregators` to read from `<A as Aggregate>::Fact::CATEGORY`.

**P3 (2 days): Rename Materializer → Projector and clean trait
surfaces.** Six trait/impl renames, all mechanical. `materialize` →
`project` method. `MultiPrefixMaterializer` → `MultiProjector`,
`TYPE_PREFIXES` → `CATEGORIES`. Delete deprecated `AnyMaterializer`.

**P4 (1 day): GROUP_NAME trait const.** Move the consumer id from
registration calls to trait consts. Update all builder methods to drop
the id parameter.

**P5 (1 day): Engine emit collapse.** Implement `Engine::emit` builder
with `.expecting(v)`. Delete `emit_in`, `append`, `append_in`. Delete
`WriteOptions`. Delete `in_context` (was never built; just confirm not
re-added).

**P6 (1 day): Aggregator registration unification.** Delete
`with_aggregate<A>` singular. `with_aggregators` handles both write
OCC and read fold; introduce `Aggregator::for_type::<A>()` constructor.

**P7 (1-2 days): CheckpointStore inversion.** Delete `ProjectionStore`.
Introduce `ProjectionOps: CheckpointStore`. Migrate the 35 conformance
tests to split between CheckpointStore (universal) and ProjectionOps
(optional). Update MemoryStore impl.

**P8 (1 day): Prelude trim.** Move non-prelude items behind module
paths. Update `lib.rs`. Audit for any external usage of removed
re-exports.

**P9 (2-3 days): Legacy deletion.** Remove `aggregator::Aggregate` +
`Apply<E>`, `reactor::Reactor` (legacy builder), `engine::Engine<D>`,
`event_log::EventLog` (the legacy one — keep `EventLogBackend`),
`reactor_queue::ReactorQueue`, `event::Event` trait,
`event_store::*`, `types::{EventPark, IntentCommit, QueueStatus, ...}`
(only the legacy ones), `job_executor::*`, `process::*`,
`reactor::{on, on_any, project}` builder functions, all legacy macros
(`#[reactor]`, `#[reactors]`, `#[projection]`, `#[event]`,
`#[aggregator]`-singular). Audit for any internal usage; rip out.

**P10 (1 day): rootsignal migration.** Apply the migration table
above. Run rootsignal's full test suite. Adjust as needed.

**P11 (0.5 day): Release.** Bump workspace to 0.4.0. Write CHANGELOG
entry. Publish.

Total: ~12-14 engineering days.

## What this doesn't do

- **Async projection runtime work.** The async-projection design from
  the deferred Track B plan is orthogonal to this release. v0.4
  doesn't ship the runtime; it ships the trait shape that the runtime
  will eventually consume. The runtime work happens in 0.5 or later.
- **Kurrent backend.** This release aligns the API surface with
  Kurrent's primitives but doesn't actually implement a Kurrent backend.
  When `causal_replay::KurrentEventLogBackend` lands later, the trait
  shapes already match — minimal adapter work.
- **Distributed reactor sharding.** Multi-process consumer groups
  sharing work is a real future feature. v0.4 supports the
  single-runner-per-group case (one Projector struct, one runner).
  The `GROUP_NAME` const is forwards-compatible with sharing.
- **Snapshot-driven projection rebuild.** `SnapshotStore` survives but
  doesn't grow new methods this release. Rebuild-from-snapshot is
  consumer-side concern (via `causal_replay::ProjectionStream`).
