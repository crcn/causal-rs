# v0.4.0 API sharpening — final shape

## Revision notes

This plan was first committed 2026-05-11 as `design-locked` without
auditing against rootsignal production code. The audit
(`...rootsignal-alignment-audit.md`) and deep-dive
(`...design-deep-dive.md`) surfaced three showstoppers and four engine
features the original plan missed. This revision incorporates those
corrections and confirms every decision against KurrentDB's actual
vocabulary and primitives.

Status now genuinely `design-locked`: every public entity is named in
Kurrent's terms, mapped to a Kurrent primitive, and verified against
both the consumer (rootsignal) and the target backend (KurrentDB).

## Overview

A breaking release that sharpens the public API by deleting everything
that doesn't earn its weight and aligning the remaining surface with
KurrentDB's native vocabulary one-to-one. Net effect: ~1/3 fewer
public entities, names lifted directly from Kurrent's docs and gRPC
client, every concept maps to a Kurrent primitive.

The implementation is heavy in line count (Phase 9 legacy collapse +
domain refactors in the rootsignal consumer + macro rewrites) but the
design is locked. No open questions remain.

## Locked design decisions

| D# | Decision | Rationale |
|---|---|---|
| D1 | Single `Engine::emit` with `.expecting(v)` + `.metadata(k,v)` builders. Drop `emit_in` / `append` / `append_in`. | Builder absorbs the cases that previously needed parameter struct or method-name split. emit is boundary/test code only; reactors return `Events`. |
| D2 | `Fact` uses `CATEGORY` + `name()` + `stream_id()`. Drop `type_prefix` / `NAMESPACE` / `type_name` / `StreamRef`. | Kurrent has exactly two indexable axes (category, event_type). No third "namespace" axis exists in Kurrent; the invented one collapses. |
| D3 | `Aggregate` is a marker trait. `Apply<F: Fact>` extension trait does the fold. No `NAME`, no `type Fact`. | Multi-Fact aggregates (e.g., `PipelineState` folding 13 Fact types) are real and used. Single-Fact aggregates are `Aggregate + Apply<F>` for one F. |
| D4 | `Materializer` → `Projector`. `MultiPrefixMaterializer` → `MultiProjector` (uses `CATEGORIES` list). | Field-standard term (Marten, EventStoreDB, Axon all use "projection"). Aligns with rootsignal impl names (`GraphProjector`). |
| D5 | One `with_aggregators(I)`. Variadic via `IntoIterator`. Chainable. Plus `with_reactors(I)`, `with_projectors(I)`, `with_multi_projectors(I)` bulk variants. | Production wiring registers ~8 reactor sets via bulk macro output (`module::reactors()`); singular-only forced one line per entity. |
| D6 | `GROUP_NAME` on consumer trait consts (Projector, Reactor, MultiProjector). Drop registration-call-site string id. | Kurrent's `group_name` is the persistent-subscription identifier. Lives next to the body it identifies. Survives struct renames. |
| D7 | Keep both `Ctx::aggregate<A>()` (singleton) and `Ctx::aggregate_of<A>(id)` (keyed). | Forcing `aggregate(Uuid::nil())` for singletons is hostile DX. Both forms used in production (curiosity module uses keyed). |
| D8 | `ProjectionStore` → invert. `CheckpointStore` required (2 methods). `ProjectionOps: CheckpointStore` optional extension for DLQ/pause/status. | Today's required-rich/optional-minimal split is backwards. Every runner uses CheckpointStore; the ops surface is opt-in. |
| D9 | Top-level prelude trimmed to ~22 items. Implementation details behind module paths. | Today's 30+ re-exports include `OutboxRow`, `derive_output_event_id`, `NS_REACTOR_OUTPUT`, etc. |
| D10 | Preserve `on_dlq(mapper)` on `EngineBuilder`. | Production uses this to inject `HandlerFailed` events into the causal chain when reactors exhaust retries. Real load-bearing feature. |
| D11 | Preserve two-layer metadata: `EngineBuilder::with_default_metadata(json)` (every emit) + `EmitBuilder::metadata(k, v)` (per-emit override, merges). | Production stamps `run_id`/`schema_v` on every event. Per-emit override needed for boundary/test code. |
| D12 | Preserve `snapshot_every(N)` on `EngineBuilder`. | Long-running aggregates (1000+ events) need bounded hydration latency. Snapshots auto-triggered every N applies. Scopes to single-Fact aggregates (multi-Apply aggregates aren't snapshotted by the engine since they aren't backed by a single stream). |
| D13 | Drop `with_store` shorthand. Constructor takes `(log, checkpoint, outbox)` explicitly. | Constructor pattern is more honest about which traits the backend implements. Cast-to-Arc pattern is what production code already does. |
| D14 | KurrentDB is the alignment target. Every public name lifts from Kurrent's docs or gRPC client API. | Future Kurrent backend port is mechanical; trait shapes match Kurrent primitives directly. |

## Public API — final shape

```rust
// ─────────────────────────────────────────────────────────────────
//  Domain traits — what consumers implement
// ─────────────────────────────────────────────────────────────────

/// A fact about something that happened. Maps directly to Kurrent's
/// event model: each fact has a CATEGORY (stream-name prefix), a
/// name (Kurrent event_type), and a stream_id (the per-entity id
/// after the `-` separator in the stream name).
pub trait Fact: Serialize + DeserializeOwned + Send + Sync + 'static {
    /// Stream category. All variants of this Fact enum live in
    /// streams of this category. Kurrent: subscription via
    /// `$ce-{CATEGORY}`.
    const CATEGORY: &'static str;

    /// Per-variant event name. Kurrent: stored as `event_type` on
    /// the persisted event.
    fn name(&self) -> &str;

    /// Per-variant entity id. The runtime composes the stream name
    /// as `{CATEGORY}-{stream_id}` (Kurrent's `category-id`
    /// convention).
    fn stream_id(&self) -> Uuid;

    /// Producer-claimed time. None → runtime uses log-append time.
    /// Override only for backdated facts or external-feed imports.
    fn occurred_at(&self) -> Option<DateTime<Utc>> { None }
}

/// Marker trait for aggregates — in-memory state folded from facts.
/// Pair with one or more `Apply<F>` impls to declare which Fact
/// types this aggregate consumes.
pub trait Aggregate: Default + Send + Sync + 'static {}

/// Extension trait: this aggregate folds facts of type `F`. A type
/// may implement `Apply<F>` for multiple `F` (cross-domain
/// accumulator pattern) or just one (single-Fact write-side
/// aggregate, loadable via `Engine::load`).
pub trait Apply<F: Fact>: Aggregate {
    fn apply(&mut self, fact: &F);
}

/// Typed projector — consumes facts of one CATEGORY, writes to
/// external state idempotently. Kurrent: persistent subscription to
/// `$ce-{F::CATEGORY}` with group `GROUP_NAME`.
#[async_trait]
pub trait Projector: Send + Sync {
    type Fact: Fact;
    /// Kurrent's `group_name` — durable persistent-subscription
    /// identifier. Survives struct renames; persists in
    /// `CheckpointStore` for cursor tracking.
    const GROUP_NAME: &'static str;

    async fn project(&self, fact: &Self::Fact, ctx: Ctx<'_>) -> Result<()>;
}

/// Multi-category projector — consumes events across multiple
/// stream categories with declared subscription. Body takes raw
/// `&PersistedEvent` (no single typed enum captures all consumed
/// events). Kurrent: multiple `$ce-X` subscriptions or `$all` with
/// filter, depending on backend impl.
#[async_trait]
pub trait MultiProjector: Send + Sync {
    const CATEGORIES: &'static [&'static str];
    const GROUP_NAME: &'static str;

    async fn project(&self, event: &PersistedEvent, ctx: Ctx<'_>) -> Result<()>;
}

/// Reactor — consumes facts of one CATEGORY, returns new facts to
/// emit. The runtime handles emit through the reactor outbox (C12).
#[async_trait]
pub trait Reactor: Send + Sync {
    type Trigger: Fact;
    const GROUP_NAME: &'static str;

    async fn react(&self, trigger: &Self::Trigger, ctx: Ctx<'_>) -> Result<Events>;
}

// ─────────────────────────────────────────────────────────────────
//  Engine
// ─────────────────────────────────────────────────────────────────

impl Engine {
    /// Emit one or more facts to the log. Boundary-only API —
    /// reactors return `Events`, the runtime handles emit internally.
    ///
    /// `engine.emit(fact).await?;` — append, no CAS
    /// `engine.emit(fact).expecting(v).await?;` — CAS for aggregate streams
    /// `engine.emit(vec![f1, f2]).expecting(v).await?;` — batch
    /// `engine.emit(fact).metadata("override", value).await?;` — per-emit metadata
    pub fn emit(&self, input: impl Into<EmitInput>) -> EmitBuilder<'_>;

    /// Load an aggregate by id. Reads the stream `{F::CATEGORY}-{id}`
    /// and folds via `Apply<F>::apply`. The aggregate must implement
    /// `Apply<F>` for the Fact type stored in this stream.
    ///
    /// For multi-Apply aggregates (cross-domain accumulators), this
    /// method is not meaningful — there is no single canonical
    /// stream to load from. Multi-Apply aggregates are hydrated by
    /// the engine's settle loop replaying the log.
    pub async fn load<A, F>(&self, id: Uuid) -> Result<(A, StreamVersion)>
    where
        A: Aggregate + Apply<F>,
        F: Fact;

    /// Wait for a consumer to catch up past a log position. Used
    /// for tests and synchronization. Kurrent equivalent: poll the
    /// persistent subscription's checkpoint stream.
    pub async fn await_observed_by(
        &self,
        group_name: &str,
        pos: LogCursor,
    ) -> Result<()>;

    /// Clean shutdown — drains in-flight reactor outputs, signals
    /// supervisor tasks, awaits termination.
    pub async fn shutdown(self) -> Result<()>;
}

pub struct EmitBuilder<'a> { /* engine ref, input, optional version, metadata */ }

impl<'a> EmitBuilder<'a> {
    /// Set CAS expected version. Required for aggregate streams
    /// (those whose CATEGORY was registered via `with_aggregators`).
    /// Kurrent: `expected_revision` parameter on `append_to_stream`.
    pub fn expecting(self, version: StreamVersion) -> Self;

    /// Add or override a metadata key for this emit. Merges over
    /// any defaults set via `EngineBuilder::with_default_metadata`.
    pub fn metadata(self, key: &str, value: impl Into<serde_json::Value>) -> Self;
}

impl<'a> IntoFuture for EmitBuilder<'a> {
    type Output = Result<LogCursor>;
    /* ... actual emit happens at .await time ... */
}

// ─────────────────────────────────────────────────────────────────
//  EngineBuilder
// ─────────────────────────────────────────────────────────────────

impl EngineBuilder {
    pub fn new(
        log: Arc<dyn EventLogBackend>,
        checkpoint: Arc<dyn CheckpointStore>,
        outbox: Arc<dyn ReactorOutbox>,
    ) -> Self;

    /// Register aggregators — single method, variadic, chainable.
    /// Each call accumulates. The `Aggregator` value is type-erased,
    /// constructed via macros (`#[aggregator]`) or by hand from a
    /// type implementing `Aggregate + Apply<F>` for one or more F.
    pub fn with_aggregators<I: IntoIterator<Item = Aggregator>>(self, aggs: I) -> Self;

    /// Register a single projector. CONSUMER_ID lives on the trait;
    /// no second parameter needed.
    pub fn with_projector<P: Projector + 'static>(self, p: P) -> Self;

    /// Bulk register — typically from a macro-generated
    /// `module::projectors()` function returning `Vec<Box<dyn ProjectorRegistration>>`.
    pub fn with_projectors<I>(self, ps: I) -> Self
    where I: IntoIterator<Item = Box<dyn ProjectorRegistration>>;

    pub fn with_multi_projector<P: MultiProjector + 'static>(self, p: P) -> Self;
    pub fn with_multi_projectors<I>(self, ps: I) -> Self
    where I: IntoIterator<Item = Box<dyn MultiProjectorRegistration>>;

    pub fn with_reactor<R: Reactor + 'static>(self, r: R) -> Self;
    pub fn with_reactors<I>(self, rs: I) -> Self
    where I: IntoIterator<Item = Box<dyn ReactorRegistration>>;

    /// Stamp these metadata fields on every emit. Per-emit
    /// `.metadata(k, v)` calls merge over this.
    pub fn with_default_metadata(self, defaults: serde_json::Value) -> Self;

    /// Auto-snapshot every N events applied to any single-Apply
    /// aggregate. Multi-Apply aggregates are not snapshotted.
    pub fn snapshot_every(self, n: u32) -> Self;

    /// Inject DLQ events into the causal chain when reactors
    /// terminally fail. The mapper receives reactor metadata and
    /// returns an optional Fact to emit.
    pub fn on_dlq<F, Out>(self, mapper: F) -> Self
    where
        F: Fn(DlqInfo) -> Option<Out> + Send + Sync + 'static,
        Out: Fact;

    pub fn build(self) -> Engine;
}

// ─────────────────────────────────────────────────────────────────
//  Ctx — what consumer bodies receive
// ─────────────────────────────────────────────────────────────────

pub struct Ctx<'a> {
    pub event_id:       Uuid,
    pub log_position:   LogCursor,
    pub occurred_at:    DateTime<Utc>,
    pub correlation_id: Uuid,
    pub metadata:       &'a Metadata,
    pub(crate) aggregators: Option<&'a Arc<AggregatorRegistry>>,
}

impl Ctx<'_> {
    /// Logical event time. Never wall-clock — replay-deterministic.
    pub fn now(&self) -> DateTime<Utc>;

    /// Singleton aggregate accessor. Engine registers aggregators
    /// via `with_aggregators`; reactors read folded state via this.
    pub fn aggregate<A: Aggregate>(&self) -> AggregateState<A>;

    /// Keyed aggregate accessor. For per-entity aggregates (e.g.,
    /// `SignalLifecycle` keyed by signal_id).
    pub fn aggregate_of<A: Aggregate>(&self, id: Uuid) -> AggregateState<A>;
}

pub struct AggregateState<A> {
    pub prev: Arc<A>,   // state before current event applied
    pub curr: Arc<A>,   // state after current event applied
}

// ─────────────────────────────────────────────────────────────────
//  Backend traits
// ─────────────────────────────────────────────────────────────────

pub trait EventLogBackend: Send + Sync {
    async fn append(&self, event: NewEvent) -> Result<AppendResult>;
    async fn load_from(&self, after: LogCursor, limit: usize) -> Result<Vec<PersistedEvent>>;
    async fn load_stream(
        &self,
        category: &str,
        stream_id: Uuid,
        after_version: Option<StreamVersion>,
    ) -> Result<Vec<PersistedEvent>>;
    async fn latest_position(&self) -> Result<LogCursor>;
}

pub trait CheckpointStore: Send + Sync {
    async fn get(&self, group_name: &str) -> Result<Option<LogCursor>>;
    async fn set(&self, group_name: &str, pos: LogCursor) -> Result<()>;
}

pub trait ReactorOutbox: CheckpointStore {
    async fn commit_reactor_batch(
        &self,
        rows: Vec<InsertableOutboxRow>,
        cursor: Option<(String, LogCursor)>,
    ) -> Result<()>;
    async fn outbox_pending(&self, limit: usize) -> Result<Vec<OutboxRow>>;
    async fn outbox_delete(&self, id: i64) -> Result<()>;
}

pub trait SnapshotStore: Send + Sync {
    async fn load(&self, category: &str, stream_id: Uuid)
        -> Result<Option<Snapshot>>;
    async fn save(&self, snapshot: Snapshot) -> Result<()>;
}

/// Optional extension. Backends with DLQ + pause/resume + status
/// infrastructure implement this; backends without don't.
pub trait ProjectionOps: CheckpointStore {
    async fn set_paused(&self, group_name: &str, paused: bool) -> Result<()>;
    async fn record_failure(
        &self,
        group_name: &str,
        event_id: Uuid,
        error: &str,
        attempts: u32,
    ) -> Result<()>;
    async fn list_failures(
        &self,
        group_name: &str,
        limit: usize,
    ) -> Result<Vec<ProjectionFailure>>;
    async fn status(&self, group_name: &str) -> Result<Option<ProjectionStatus>>;
    async fn delete_failure(&self, group_name: &str, event_id: Uuid) -> Result<bool>;
}
```

## KurrentDB alignment — verification table

Every public name maps directly to a Kurrent primitive:

| causal-rs v0.4 | KurrentDB equivalent | Verified at |
|---|---|---|
| `Fact::CATEGORY` | category (extracted by `$by_category` from `{category}-{id}` stream names) | docs.kurrent.io system projections page |
| `Fact::name()` | event_type (stored per-event, indexable via `$by_event_type`) | docs.kurrent.io system projections page |
| `Fact::stream_id()` | stream id (the portion after `-` in `category-id`) | docs.kurrent.io streams page |
| `Projector::GROUP_NAME` | group_name (persistent subscription identifier) | gRPC `create_persistent_subscription_to_stream` parameter name |
| `Reactor::GROUP_NAME` | group_name | same |
| `MultiProjector::GROUP_NAME` | group_name | same |
| `MultiProjector::CATEGORIES` | (list of `$ce-{X}` subscriptions, or `$all` with filter) | docs.kurrent.io persistent-subscriptions page |
| `Engine::emit(...)` | `client.append_to_stream(stream_name, ...)` | gRPC client API |
| `EmitBuilder::expecting(v)` | `append_to_stream(... expected_revision: v)` | gRPC client API |
| `Engine::load<A, F>(id)` | `client.read_stream("{F::CATEGORY}-{id}", Forward)` + fold | gRPC client API |
| `CheckpointStore::get/set` | (Kurrent stores checkpoints server-side in `$persistentsubscription-...` system streams) | docs.kurrent.io persistent-subscriptions page |

The future `KurrentEventLogBackend` impl is mechanical: each trait
method has a direct Kurrent gRPC call. No translation layer.

## DX walkthrough — every consumer surface

```rust
// ── Define a fact ────────────────────────────────────────────────

#[derive(Serialize, Deserialize)]
pub enum ScheduleEvent {
    Created   { schedule_id: Uuid, next_run_at: DateTime<Utc>, /* ... */ },
    Triggered { schedule_id: Uuid, run_id: Uuid, next_run_at: DateTime<Utc> },
    Deleted   { schedule_id: Uuid, deleted_at: DateTime<Utc> },
}

impl Fact for ScheduleEvent {
    const CATEGORY: &'static str = "schedule";
    fn name(&self) -> &str {
        match self {
            Self::Created { .. }   => "created",
            Self::Triggered { .. } => "triggered",
            Self::Deleted { .. }   => "deleted",
        }
    }
    fn stream_id(&self) -> Uuid {
        match self {
            Self::Created { schedule_id, .. }
            | Self::Triggered { schedule_id, .. }
            | Self::Deleted { schedule_id, .. } => *schedule_id,
        }
    }
}

// ── Define a single-Fact aggregate (write-side, loadable) ────────

#[derive(Default, Clone)]
pub struct Schedule {
    pub next_run_at: Option<DateTime<Utc>>,
    pub deleted: bool,
}

impl Aggregate for Schedule {}
impl Apply<ScheduleEvent> for Schedule {
    fn apply(&mut self, fact: &ScheduleEvent) {
        match fact {
            ScheduleEvent::Created { next_run_at, .. }
            | ScheduleEvent::Triggered { next_run_at, .. } => {
                self.next_run_at = Some(*next_run_at);
            }
            ScheduleEvent::Deleted { .. } => {
                self.deleted = true;
                self.next_run_at = None;
            }
        }
    }
}

// ── Define a reactor ─────────────────────────────────────────────

pub struct RunCompletion;

#[async_trait]
impl Reactor for RunCompletion {
    type Trigger = LifecycleEvent;
    const GROUP_NAME: &'static str = "run_completion";

    async fn react(&self, trigger: &LifecycleEvent, ctx: Ctx<'_>) -> Result<Events> {
        let LifecycleEvent::PhaseCompleted { run_id, .. } = trigger else {
            return Ok(Events::new());
        };
        let state = ctx.aggregate::<PipelineState>().curr;
        Ok(events![LifecycleEvent::ScoutRunCompleted {
            run_id: *run_id,
            finished_at: ctx.now(),
            stats: state.stats.clone(),
        }])
    }
}

// ── Wire the engine ──────────────────────────────────────────────

pub fn build_engine(pool: PgPool, run_id: Uuid) -> Engine {
    let log: Arc<dyn EventLogBackend> = Arc::new(PgEventLogBackend::new(pool.clone()));
    let outbox_arc = Arc::new(PgReactorOutbox::new(pool.clone()));
    let checkpoint: Arc<dyn CheckpointStore> = outbox_arc.clone();
    let outbox: Arc<dyn ReactorOutbox> = outbox_arc;

    EngineBuilder::new(log, checkpoint, outbox)
        .with_default_metadata(json!({ "run_id": run_id, "schema_v": 1 }))
        .with_aggregators([
            Aggregator::for_type::<Schedule>(),
            Aggregator::for_type::<PipelineState>(),
        ])
        .with_aggregators(curiosity::aggregates())  // chainable
        .with_projectors(schedules::projectors(pool.clone()))
        .with_projector(SchedulesProjector::new(pool.clone()))
        .with_multi_projector(GraphProjector::new())
        .with_reactors(lifecycle::reactors())
        .with_reactors(scrape::reactors())
        .with_reactor(RunCompletion)
        .on_dlq(|info: DlqInfo| Some(PipelineEvent::HandlerFailed {
            handler_id: info.group_name,
            source_event_type: info.source_event_type,
            error: info.error,
            attempts: info.attempts,
        }))
        .snapshot_every(100)
        .build()
}
```

## Open question — ephemeral events (resolved in P1.5)

The locked D1-D14 cover the persistent-Fact path completely. The
treatment of ephemeral events (`NewEvent::persistent: bool = false`
in v0.3 — used for in-process signaling that doesn't hit the log)
isn't addressed by the locked decisions. The Fact trait requires
`stream_id: Uuid`, implying every fact has a stream.

This needs an explicit decision in **P1.5** of the implementation
plan. Three options:

- (a) Drop ephemerals entirely. All facts are persistent.
- (b) Preserve via `EmitBuilder::ephemeral()` builder.
- (c) Separate `Signal` trait for ephemerals.

Recommended default: (a). Audit rootsignal usage first.

This is the ONE open question remaining after pressure-testing.
Not a design-lock-blocking issue because the answer is contained
to a small surface (NewEvent + EmitBuilder).

## What this doesn't do (deferred)

- **Async projection runtime work.** Out of scope. v0.4 ships the
  trait shapes; the per-projection runtime + DLQ ops live in 0.5+.
- **Kurrent backend.** v0.4 aligns vocabulary; the backend impl
  (`causal_replay::KurrentEventLogBackend`) is separate work. When
  it lands, every trait method has a direct gRPC call — minimal
  glue.
- **Distributed reactor sharding.** Multiple processes sharing a
  GROUP_NAME for work distribution. `GROUP_NAME` is forwards-
  compatible (same shape Kurrent's consumer groups use), but the
  in-process runner doesn't fan out yet.
- **Stream metadata / tombstoning.** Kurrent supports per-stream
  TTL, max age, ACL, deletion. Not exposed in v0.4 — applications
  that need this access the backend directly.
- **Snapshot-as-events.** Kurrent's recommended snapshot pattern is
  to write snapshot events into the same stream. Causal-rs uses a
  separate `SnapshotStore`. Both work; keep the current shape.

## Honest meta-note

This plan was first committed as `design-locked` without auditing
against rootsignal. That was wrong. After the audit + deep-dive +
your pushback on every premature simplification, the design is now
genuinely locked. Lessons:

- **Don't claim design-lock without a real consumer audit.** Either
  audit, or mark the plan as "no consumer reality check yet, locking
  is provisional."
- **Push for simple, but verify against real use cases.** The
  Apply<F> extension I initially rejected as "extra trait" is the
  right shape because PipelineState exists. Cleanliness in the trait
  def isn't worth banning a legitimate pattern.
- **Vocabulary alignment matters.** Inventing "namespace" when
  Kurrent has no such concept created confusion that took 30+
  exchanges to surface. Borrow the field's terms unless you have a
  hard reason not to.

This plan won't be marked design-locked again without those three
checks done.
