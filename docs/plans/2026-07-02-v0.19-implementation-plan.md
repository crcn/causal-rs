# causal 0.19.0 — implementation plan

Executable plan for the post-audit hardening release. The **what/why** lives in
the companion design doc `2026-07-02-decision-records-design.md` (read it first —
including "Amendments after adversarial attack" A1–A7 and "DX hardening" D1–D8,
which are binding). This doc is the **how/in-what-order**: phases, blocking
dependencies, the test to write first for each, and the exit gate.

Every defect here was verified against code; the keystone (chimera) was
reproduced against shipped 0.18.0. Two facts drive the ordering:

- **The decision-record completion path is only correct on Kurrent once global
  event_id dedup exists.** Kurrent's `append_any_idempotent` dedups within a
  `max(4·batch, 64)`-event tail window only (`kurrent_event_log.rs:130`) — a
  re-append buried deeper duplicates. So **Phase 1 (Kurrent global dedup)
  precedes Phase 2 (records)**, and Phase 2's first test is the tripwire that
  fails until Phase 1 is in.
- Everything else is independent and can land in any order after its own tests.

Work TDD: write the RED test named in each item, then make it green.

## Phase 0 — test-suite honesty (do this first; it gates trust in everything else)

The PG/Kurrent conformance suites are `#[ignore]`d and run in a CI job marked
`continue-on-error: true`; the Any-redelivery scenario buries the original under
exactly ONE foreign event (inside the 64-window), so it passes while the
property it names is void at depth. Until this is fixed you cannot trust a green
suite.

- [ ] Un-`#[ignore]` the PG and Kurrent conformance suites; remove
      `continue-on-error` from that CI job (provision the containers instead).
- [ ] Add depth to the Any-redelivery scenario: a variant that buries the
      original under >64 foreign events. **Expected: RED on Kurrent today** —
      this is the Phase 1 acceptance test, pre-written.
- [ ] Add a divergent-payload-at-depth scenario (same event_id, different
      payload, >64 deep): RED on Kurrent today (silently accepted).
- [ ] Wire C1c placement-divergence for the Kurrent backend (currently exempted).

**Exit:** the suites run for real in CI; the two new depth scenarios are RED on
Kurrent and GREEN on memory/PG (proving the gap is backend-specific).

## Phase 1 — Kurrent global event_id dedup (keystone #2; blocks Phase 2 completion path)

**Problem:** dedup/divergence on Kurrent is tail-window-bounded; beyond ~64
events an identical redelivery duplicates and a divergent one lands silently.
Memory and PG dedup absolutely. Fix the module doc too — it claims the opposite
of the actual behavior.

- [ ] Add a global event_id registry consulted on every Any-append. Obvious
      shape (design freely): a PG-side `causal_event_ids(event_id UUID PRIMARY
      KEY, stream TEXT, position …)` written in the same path that appends to
      Kurrent, checked before the tail-window scan. PG is already required
      infrastructure, so this adds no new dependency.
- [ ] `append_any_idempotent`: consult the registry first; on hit, return the
      recorded position (true idempotency) instead of re-scanning the tail.
- [ ] Divergence check keys off the registry, not the window — a same-id
      different-payload append is rejected regardless of depth.
- [ ] `ensure_schema` + exported `*_SCHEMA_SQL` for the new table (do not repeat
      the divergences-table footgun).
- [ ] Correct the `kurrent_event_log.rs` module doc.

**RED test first:** the Phase 0 depth scenarios flip to GREEN on Kurrent.

**Exit:** Any-append idempotency and divergence rejection hold at arbitrary
depth on all three backends; conformance proves it.

## Phase 2 — Decision records (keystone #1)

Implement per the design doc, **with amendments A1–A7 binding**. Depends on
Phase 1 for its completion path.

**RED test first (the tripwire, D2):**
- [ ] `completion_path_is_idempotent_on_a_deep_stream` — run the completion path
      against a Kurrent stream whose recorded outputs are buried >64 events
      deep. With Phase 1 in, GREEN; without it, RED (duplicates). This makes the
      Phase 1 → Phase 2 dependency executable, not documentary.
- [ ] `nondeterministic_body_cannot_produce_a_chimera` — port the reproduced
      0.18 chimera test; it is RED against pre-records behavior, GREEN after.

Then the design-doc mechanics:
- [ ] `DecisionStore` trait + `DecisionRecord` (full `EventData` outputs).
- [ ] Memory + PG backends; PG mirrors `PgEffectStore`'s first-write-wins CTE —
      **handle the zero-row race** (A4: concurrent first-writes can return no
      rows; retry the SELECT).
- [ ] `ensure_schema` + `DECISION_SCHEMA_SQL`.
- [ ] Runner: `decisions.get()` before body dispatch — hit ⇒ completion path
      (append missing outputs from record → ack → floor), miss ⇒ attempt path
      with `seal` between body success and the append loop; loop iterates
      `sealed.outputs`. `derive_output_event_id` moves to seal time.
- [ ] **Completion path replicates the per-append side channels (A5):** the
      settle high-water bump (`reactor_runner.rs:1396-1398`) and best-effort
      engine-registry fold (`:1399-1429`). Omitting these lets `settle()` return
      before catch-up appends drain downstream.
- [ ] **Seal failure = runner-infra retry, never park (A4):** same arm as append
      I/O errors. Sanitize `\u0000` (and other JSONB-rejected sequences) from
      payload strings at seal — scraped content contains them and an unsanitized
      seal fails deterministically → permanent wedge under infra-retry.
- [ ] **GC is retention-based, not floor-based (A1):** age-based (config, days),
      floor as a minimum bound — never remove a record younger than retention or
      un-passed by the floor. Prevents zombie-racer re-seal (the leasor has no
      fencing token).
- [ ] **Divergence handling is record-gated (A3):** on divergence, consult the
      store — record present ⇒ loud (park, integrity error); record absent ⇒
      accept-and-advance with a warn (we verifiably forgot; re-deciding was
      correct). Do NOT make it unconditionally loud — that park-storms on every
      checkpoint regression.
- [ ] **Empty records: benchmark before shipping (A6).** Measure decision-write
      volume on a fan-out workload. If it dominates, fall back to a compact
      decided-empty marker on the reactor-checkpoint row or empty-seal elision
      for side-effect-free consumers. Do not silently ship full empty records.
- [ ] Delete divergence *handling* (accept-and-advance path, `reactor_divergence`
      redelivery traffic, `first_diff_path` on that path). Keep
      `DivergentRedelivery` in backends as the record-gated integrity assert.
      Mark the divergences table deprecated (drop in 0.20).

Behavior tests from the design doc: `sealed_decision_replays_without_reexecuting
_the_body`, `crash_after_partial_append_completes_the_batch_from_the_record`,
`racing_executions_adopt_the_first_sealed_decision`, `zero_output_reaction_...`,
`crash_before_seal_re_decides_and_that_is_correct`, `body_failure_retries_then_
parks_without_sealing`, `gc_removes_records_behind_retention_and_never_live_ones`,
`engine_with_reactors_and_no_decision_store_refuses_to_build`.

**Exit:** chimera test GREEN; builder gate rejects a reactor engine without a
decision store; all behavior tests pass on all three backends.

## Phase 3 — independent correctness fixes (any order, parallelizable)

Each is self-contained; none blocks another.

- [ ] **Settle liveness ceiling default-on + per-attempt react timeout** (audit
      item 3, D3). Ceiling default ~30s, explicit opt-out. Per-attempt `react`
      timeout (a hung effect hangs even *with* the ceiling — supervisor
      heartbeats Idle), configurable, with `.with_attempt_timeout(...)`
      per-reactor override. Typed `SettleTimeout { workflow_id, last_progress }`
      — never stringy anyhow; docs state the work continues.
      *Test:* dead-supervisor errors settle within ceiling; never-returning
      react is interrupted at the attempt timeout, not left hanging.
- [ ] **Projector park parity for `PgEventProjector`** (audit item 4). Route it
      through `ProjectionRunner`/`MultiProjectorRunner` or give it the same
      poison-park taxonomy. Also surface live-mode skip-and-advance
      (`stream.rs:355-361`) as an observable counter/log, not silent.
      *Test:* a poison event parks and the cursor advances; hydration skips it.
- [ ] **Fold cold-cache fix** (audit item 5). `fold_bounded`'s incremental
      cache dies when the partition worker exits on queue-drain; phase-chained
      workflows re-fold cold. Make `fold_bounded` snapshot-aware or persist the
      worker cache across worker lifecycle (keyed by partition).
      *Test:* a chained workflow folds O(gap), not O(stream), across a
      worker-exit boundary — assert read count.
- [ ] **Snapshot save race** (audit item 6). `maybe_save_snapshots` reads
      `get_version` and `get_state` separately; a fold between them persists a
      snapshot claiming fewer events than it holds → restore double-folds the
      tail. Take version+state under one entry guard.
      *Test:* concurrent fold during save cannot produce a snapshot whose
      revision disagrees with its blob.
- [ ] **H8 snapshot fold-version tag** (audit item 7, small). Author-bumped
      const stamped into snapshots; mismatch on load ⇒ discard + rebuild, log at
      info.
      *Test:* a snapshot with a stale fold-version is discarded, not trusted.

## Phase 4 — write-path hygiene (demoted; not the June root, still real)

- [ ] **Batch PgReactorObserver INSERTs** — the dominant writer during replay
      storms (the June incident's heavy load, not checkpoints). Already
      channel-buffered; coalesce into multi-row INSERTs.
- [ ] **Checkpoint debounce** (time-or-delta flush) with forced flush on
      drain/shutdown and before settle-dependent reads.
- [ ] **Retention/GC** for executions/logs/divergences/effects/snapshots —
      `ensure_schema`-style helpers + documented SQL for external schedulers.

## Phase 5 — DX hardening (ships with 0.19 unless noted; see D1–D8)

- [ ] **D1 — `EngineBuilder::in_memory_for_tests()`**, in the SAME PR as the
      decision gate (Phase 2). One call wires MemoryStore into every slot and
      satisfies both `allow_in_memory_*_for_tests` gates. The gate must not land
      without it or every downstream test harness churns twice.
- [ ] **D4 — boot-time orphan detection.** Warn loudly at build for
      checkpoint/decision/effect rows whose consumer id is unregistered ("did
      you rename?") and for log event kinds with no registered fold/trigger.
      Optional hard-fail flag for CI. (The rename trap — highest-likelihood
      brittleness in a fast-renaming codebase.)
- [ ] **D5 — fold determinism self-check (test engines only).** Fold each
      hydrated stream twice in in-memory engines, compare, name the first
      differing subject. Folds are the one place a dev mistake still silently
      corrupts post-records. (Right for folds; the killed double-run idea was
      wrong for reactors because the runtime no longer re-runs them.)
- [ ] **D6 — duplicate effect-label debug assert.** Within-reaction label reuse
      panics in debug.
- [ ] **D3 — typed `SettleTimeout` + per-reactor react-timeout override** — done
      in Phase 3.
- [ ] **D7 — ship the lint config in-crate.** `clippy.toml` snippet in `lints/`
      (`Uuid::new_v4`, `Utc::now` disallowed in reactor modules), referenced
      from reactor-authoring docs.
- [ ] **A7 — rename `skip_gap_on_start` → `start_at_latest_dropping_gap`**,
      deprecated alias one release, loud skipped-range log at start.

## Deferred to 0.20 (design only in this cycle)

- [ ] **H2 event upcaster seam** — design doc; largest item; gates downstream's
      first un-nukeable production data.
- [ ] **D8 Ctx-only I/O** — design doc. Deps reachable only via an
      effect-scoped accessor (`ctx.io(label, |deps| ...)`), making unmemoized

      Records make it non-urgent (failure mode is cost, not corruption).

## Withdrawn — do NOT build (verified non-issues / subsumed)

- **Park-order swap** — the ordering is deliberate (`reactor_runner.rs:
  1507-1510`: a failed park append must not reset the retry budget); the wedge
  branch is unreachable (attempt counters are process-local DashMaps, `clear`
  infallible). Leave it.
- **Double-run determinism verification for reactors** — dead under records.
  (Its idea survives only for *folds*, as D5.)
- **H6 atomic multi-output via backend trait changes** — subsumed by records
  (the record is the atomicity).
- **Static reactor cycle detection** — deferred; the H7 depth ceiling stands.
